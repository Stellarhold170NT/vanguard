## 2. Thiết kế — quyết định chính trong `.goreleaser.yaml`

1. **CGO là bắt buộc**: `CGO_ENABLED=0 go build ./cmd/vanguard` FAIL — `github.com/smacker/go-tree-sitter/java: build constraints exclude all Go files` (grammar tree-sitter là cgo, charter B-1). Vì vậy cross-compile 5 target còn lại cần C cross toolchain → **`zig cc`**.
2. **Cả 6 targets (kể cả linux/amd64 "native") đều pin zig** (`CC=zig cc -target …`, linux dùng musl → ELF static) — build không bao giờ phụ thuộc C compiler của máy chạy, sandbox-verify == CI code path, tái lập từ tag (R4/brief: "Mọi build phải tái lập được từ tag").
3. **ldflags** nối `main.version/commit/date` (w2-06 contract): `{{.Version}}` = tag, `{{.FullCommit}}`, `{{.Date}}` (RFC3339 UTC). Đã thấy thật trong log build: `-X main.version=0.1.0-sbx-test -X main.commit=0ec185633c65e4233ab5b8c85a094832f66e9fb0 -X main.date=2026-10-09T23:08:20Z`.
4. **mod_timestamp: '{{ .CommitTimestamp }}'** đặt trong `builds` (goreleaser v2 dời field này từ `archives` — `goreleaser check` v2.18.3 bắt ngay: `line 82: field mod_timestamp not found in type config.Archive`): binary mang mtime của tag commit. Hạn chế còn lại: members LICENSE/README trong archive vẫn mang mtime checkout (tool không hỗ trợ) — đã ghi §7.
5. **Archives**: tar.gz mặc định, zip override cho windows; `checksums.txt` sha256; kèm LICENSE + README.
6. **Changelog filters** sửa so với draft cũ: repo dùng conventional commits **có scope** (`docs(w5-06): …`) nên pattern `^docs:` của draft mặc định sẽ KHÔNG loại được — dùng `^docs` / `^test` / `^chore` / `^ci` / `^build` / `^style` / `^Merge` (prefix trùm cả hai style).
7. **`release: draft: false, prerelease: auto`**; bỏ hardcode `github.owner/name` — goreleaser tự detect từ origin remote (nguồn sự thật duy nhất, sống sót qua rename repo).
8. **`-buildvcs=false` + `-trimpath`**: build không nhét VCS state lệch vào binary; artifact tái lập từ tag.

## 2b. darwin link fix — `internal/buildconf` (điểm đổi code duy nhất)

Cross-build darwin (cgo) đâm 2 lỗi link lần lượt, cả hai đều là **hard-coded flag của Go toolchain mà config không tắt được**:

| Lỗi | Nguồn root-cause (đọc GOROOT trong sandbox) | Fix |
|---|---|---|
| `unable to find dynamic system library 'resolv'` | `net/cgo_unix_cgo_res.go:21` `#cgo !android,!openbsd LDFLAGS: -lresolv` **và** cứng hơn: `internal/syscall/unix/net_darwin.go:41` `//go:cgo_ldflag "-lresolv"` — flag áp cho mọi build cgo darwin; thử `netgo`/`osusergo` KHÔNG hiệu quả (file thuộc package khác, không có escape) | stub **`libresolv.tbd`** (Apple text-based dylib stub, tbd-version 4, install-name `/usr/lib/libresolv.9.dylib`, 3 symbol `res_9_ninit/nsearch/nclose`) + `#cgo LDFLAGS: -L${SRCDIR}` |
| `unable to find framework 'CoreFoundation'` | `runtime/cgo/cgo.go:15` `#cgo darwin,arm64 LDFLAGS: -framework CoreFoundation`; zig bundle chỉ có `libSystem.tbd`, không có framework stub. Code CF trong `gcc_darwin_arm64.c` nằm trong `#if TARGET_OS_IPHONE` = dead code trên macOS → **không symbol nào cần bind** | stub framework **rỗng exports**: `Frameworks/CoreFoundation.framework/CoreFoundation.tbd` + `#cgo LDFLAGS: -F${SRCDIR}/Frameworks` |

Wiring: `internal/buildconf/darwin_cgo.go` (`//go:build darwin && cgo`, preamble `#cgo LDFLAGS: -L${SRCDIR} -F${SRCDIR}/Frameworks`) + blank import trong `cmd/vanguard/main.go`. `${SRCDIR}` được go tool mở rộng thành absolute dir của chính file đó → **không có path phụ thuộc môi trường** (CI = sandbox = local dùng cùng 1 nguồn). Runtime: no-op trên mọi platform; trên macOS thật binary load libresolv.9.dylib hệ thống như thường (install-name khớp). `doc.go` giải thích mục đích package.

Bẫy cgo đã đâm: comment prose **kề sát `import "C"` bị biên dịch như C preamble** — `error: unknown type name 'Point'` (từ "Point the C linker…"). Fix: khối giải thích tách riêng, preamble chỉ chứa `#cgo`.

Bẫy tbd: dialect **v3 bị từ chối** bởi lld của zig 0.16 (`failed to parse TBD file: NotLibStub`) — dùng **`tbd-version: 4`** khớp đúng dialect của `libSystem.tbd` do zig tự ship (`/usr/lib/zig/libc/darwin/libSystem.tbd`).

## 5. SOP — Release Vanguard v0.1.0 (w6-04 thực hiện theo)

1. Tree sạch trên `main`, chứa commit w6-01 (branch `agent-w6-01 @ <SHA>` đã merge — §8).
2. **zig ≥ 0.16** trên máy chạy release thủ công (CI tự có qua `mlugg/setup-zig@v1`). Không cần cài goreleaser trước — CI dùng action; nếu chạy tay: dùng đúng **goreleaser v2.18.3** (SOP pin; sha256 trong §3.1), hoặc thêm vào SOP cache: tải tarball 1 lần vào `/usr/local/bin` (26.7 MB, ~5-10s trên sandbox).

### 5.1 Quy trình chuẩn (đúng kịch bản CI)

### 5.3 Bẫy đã kiểm chứng trong phiên này
1. **Không tag / dirty tree** → goreleaser từ chối ở bước validate (mode release). Dry-run không tag phải thêm `--snapshot`.
2. **`mod_timestamp` đặt sai section** (archives thay vì builds) → `goreleaser check` fail — dùng v2 schema.
3. **darwin cross-build** cần 2 tbd stub trong repo (đã có — `internal/buildconf`); nếu clone thiếu (mất trong merge) → darwin targets fail ở link. Đừng thử "fix" bằng `netgo`/`osusergo` — flag `-lresolv` nằm ở `internal/syscall/unix`, build tag không loại được (đã thử, §3.4 run 4-5).
4. **Quên push tag** = workflow không bao giờ chạy (trigger duy nhất là tag push).
5. Chạy trong vai-sandbox: dùng pattern nohup + log file + EXIT marker (§3.4 lesson 1), `timeout` rõ ràng ≤ 1500s.

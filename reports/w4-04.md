## 5. Five typical FP disputes (dry-run verdicts + conclusions + aip.dev)

1. **`login` → R2xx-02 create-shaped (F-009, WARN)** — the create-shaped predicate (`rules/methods.go createShapedPath`) treats any POST whose method-level path carries no action-lexicon token as "create"; `login` is not in `actionVerbs` (deliberately minimal lexicon). [google.aip.dev/133](https://google.aip.dev/133) (Create: standard create returns 201 for a *resource*) — but login is a custom action, which AIP governs in [google.aip.dev/136](https://google.aip.dev/136) (custom methods; vanguard re-states this as "action-shaped path/token" in Spring terms). **Conclusion: FP (heuristic-context)** — the heuristic over-fires on auth verbs; the finding's own wording ("verify that this POST creates") is honest WARN-level hedging.
2. **`byte[]` export → R3xx-02 bare collection (F-018, F-022)** — the bare-base predicate treats `byte[]` like a bare JSON array ("no room for total/page metadata"). [google.aip.dev/158](https://google.aip.dev/158) (Pagination) speaks about List methods returning *collections of resources*; a binary file download is not a resource collection. **Conclusion: FP (heuristic-context)** — exclude binary download types (`byte[]`, `Resource`) from the bare-base set. This also resolves the ok-007 anchor contradiction (§3.3).
3. **`/api` route index → R1xx-01 + R3xx-01/02 (F-023)** — "api" is singular so R1xx-01 fires on a GET collection, and the unpaginated checks pile on. [google.aip.dev/131](https://google.aip.dev/131) (List) + [google.aip.dev/122](https://google.aip.dev/122) (resource names) apply to resource collections; `/api` is an infrastructural version prefix and the route index is an aggregate. **Conclusion: FP (heuristic-context)** — the root cause is the unregistered R6xx-03 (bare `/api` policy rule, declared gap dm-04); until R6xx-03 lands, w5-04 should allowlist infra segments.
4. **`/search/…` path segment → R2xx-05 on GET (component of F-011/F-012/F-017/F-025, INFO)** — "search" is an action-lexicon token, so any non-POST with it in the path fires "looks like an action — verify manually". [google.aip.dev/136](https://google.aip.dev/136) permits custom methods with side-effect-free GET semantics, so a GET search endpoint is not automatically wrong. **Conclusion: FP-leaning (heuristic-context)** at INFO — the rule is a verification hint by design; the w5-04 question is whether GET+search deserves a lower severity or a method-name-vs-path-segment split.
5. **Alignment artifact — two slots one row (as-034+as-035 both folded into F-007)** — both R4xx-02 claims sat within the ±4 window of the same span, so the matcher over-assigned as-035 to F-007 (created_date row F-008 still matched as-036; rule metrics unaffected because folding is per-row). Protocol-side conclusion: this is a **harness alignment artifact, not a product FP** — recorded for the w5-04 harness owner (make slot→row assignment one-to-one when counts must be slot-exact). Underlying rule citations [google.aip.dev/140](https://google.aip.dev/140).

Tie-break applied throughout: FP-first (charter §7) — uncertain rows labeled FP with a tuning proposal, never TP "for safety".

## 6. Tuning proposals for w5-04 (from dry-run evidence only)

2. **R2xx-02**: extend the documented `actionVerbs` lexicon (or add an auth-verb exemption) with `login`/`logout`/`register`-class tokens; extend only with a fixture-backed case per the lexicon's own discipline note.

## 2. Deliverables — 5 rule data-first + đọc proto khai báo + IR extension

| Rule | Sev | Điểm bắn | Heuristic (tóm tắt — chi tiết trong `docs/rules/`) |
|---|---|---|---|
| `R5xx-01` unified-error-shape | WARN | ErrorHandler | option `scheme`: `auto` (mặc định) suy chuẩn từ ErrorScheme — envelope ≥2 handler chia sẻ, strictly-greatest, **resolvable trong `ctx.Surface.Types`**; chuẩn không chứng minh được → im lặng; handler lệch (kể cả `Map<String,Object>` không resolve được) bị bắn. `code-message-details` / `problem-json`: field-check (effective JSONName‖Name) trên type resolve được; scheme lạ → panic → diagnostic §5.4 |
| `R5xx-02` no-500-for-business | ERROR | ErrorHandler | hiệu lực 500 (StatusCode, fallback ExceptionStatus — đúng thứ tự resolve của Spring) + **app-owned** (`ExceptionPackage != ""` — adapter resolve từ repo) + suffix `Exception`; fallback ngoại lai `Exception.class` và tên không suffix im lặng (FP-first) |
| `R5xx-03` status-semantics | WARN | Method | POST + status hiệu lực 200 (khai báo **hoặc** ngầm 0 — IR quy ước "0 = không khai báo, suy theo verb") + response đơn (không collection) + path create-shape (segment cuối literal, không `{`, không `:`, không thuộc bộ ~55 action word exact-token) |
| `R6xx-01` versioned-path | WARN **default-OFF** | Service | `BasePath` không match pattern (mặc định `/v[0-9]+` — segment-anchored; option `versionPattern` là Go regexp); pattern hỏng → panic → diagnostic; `""` im lặng |
| `R6xx-02` grpc-standard-methods | INFO | GrpcService | rpc không phải Standard prefix (Get/List/Create/Update/Delete/Batch*/Search + noun camel) và không phải VerbNoun (first camel word ∈ bộ action verb ~50, ≥2 từ); option `allow` là lối thoát có lý do; message nêu cả service+rpc |

**IR extension (w3-06)**: `ir.ErrorHandler` += `ExceptionPackage` (chuỗi rỗng = external/undeclared — tín hiệu sở hữu của R5xx-02) + `ExceptionStatus` (@ResponseStatus trên chính lớp exception, 0 = không có) — `validate.go` range-check như StatusCode. Adapter resolve qua `buildClassIndex` (simple name → declaration, gồm nested, first-wins — mirror `buildTypeIndex`).

**Đọc proto khai báo** (`adapters/spring/grpc.go`, mới): mini-reader chỉ nhận `service <Name> { … }` + `rpc <Name>(` — đúng cap v0.1 của brief (tránh bẫy raw-proto-parser); strip comment (// và /* */, giữ newline, tôn trọng string literal) nên offset vẫn map đúng dòng/cột; file lạ (brace lệch, `service` không tên/thân, không đọc được) **im lặng bỏ qua** — repo không proto = skip sạch (acceptance w3-06); service bị comment out vô hình; emit theo thứ tự file × khai báo, Location trên từ khóa `service`.

Fixture e2e `testdata/spring-errors/` (pom + 7 java + 1 proto + README bảng positive/negative): GlobalExceptionHandler {R5xx-01 ×1 (Map deviator), R5xx-02 ×1 (BusinessException→500)}, OrderController {R5xx-03 ×2 (200 tường minh + ngầm)}, library.proto {R6xx-02 ×1 (DoMagic; SyncData/ArchiveBook hợp lệ, GhostService comment out bị loại)} — pin bằng scan test full-pipeline `rules/errors_scan_test.go` (package `rules_test`).
